# 内部账目管理平台 — 业务需求方案

> 版本：v0.4 业务版 日期：2026-11-03
> 说明：本文档只描述业务需求，技术实现另见《需求方案》。

---

## 1. 背景与目标

公司内部资金流转存在大量"非标准路径"：公户转个人、个人取现、现金交付第三方、第三方再经对公账户回款等。传统记账方式只记录"公司账户的收支"，无法回答以下问题：

- 这 10 万元从公户 A 转出后，最终去了哪里？还有多少滞留在个人手里？
- 某项目到目前为止真实花了多少钱，其中材料、工资、报销各多少？税费多少？
- 李老板转入公户 B 的这笔钱，对应的是当初哪一笔出款？

**目标**：建立一个以**项目**为核心、以**资金流转链**为特色、账实可核对、可审计的内部账目平台。

### 1.1 现状

目前每个公司主体各用一个 Excel 记"银行日记账"（序号 / 交易日期 / 用途 / 收入 / 支出 / 余额 / 备注），共涉及 **30 家主体**。现有台账的主要业务缺口：

- 没有项目、账目类型字段，项目和资金去向只能写在备注里，无法汇总、无法追踪
- 只记银行账户，个人代管资金、现金不在账上
- 宁晓花、杨燕花等个人账户同时为多家公司周转，余额无人统一掌握
- 公司之间的往来两边各记一笔，彼此没有关联
- 银行回单上的用途与实际用途经常不一致

现有台账今后只作为历史数据来源，由财务人工转录到新模板后导入系统（见 4.7.2）。

## 2. 用户角色

| 角色 | 典型人员 | 主要权限 |
|---|---|---|
| 超级管理员 | IT/老板 | 系统配置、用户与权限、全部数据 |
| 财务 | 会计、出纳 | 录入/审核流水、对账、税费、导入导出、结账 |
| 项目负责人 | 项目经理 | 查看本项目账目、发起报销/付款申请、审批本项目支出 |
| 经办人 | 普通员工 | 提交报销、查看自己经手的资金（如个人账户代收代付余额） |
| 只读审计 | 老板/外部审计 | 全局只读 + 操作记录 |

权限可以按 **公司主体 × 项目 × 账户** 细分（例如某会计只负责擎宇、凌岳两家公司；某项目经理只能看到 X、Y 两个项目）。

## 3. 核心业务概念

平台围绕五个概念组织：**公司主体、账户、资金流水、资金来源（溯源）、项目**。

### 3.1 公司主体
平台同时管理 30 家公司主体，一般纳税人与小规模纳税人并存，分公司独立报税。

- 基本信息：名称、简称、统一社会信用代码、类型（总公司/分公司/独立公司）、上级主体、所在地、主管税务机关
- **纳税人身份**：一般纳税人 / 小规模纳税人，记录变更日期（小规模转一般纳税人后，之前期间仍按小规模计算）
- 税务配置：增值税申报周期（月/季）、适用税率或征收率、附加税优惠（如小规模"六税两费"减半）、所得税核定/查账征收
- 默认账户、负责会计

归属规则：
- 对公账户属于某一主体；**内部个人账户、现金账户不属于任何主体**（一个人可能同时为多家公司周转），每笔钱来自哪家公司通过"资金来源"记录
- 项目属于承接合同的主体；一个项目由多家公司共同承担时，按主体拆成子项目
- 两端都是本平台主体对公账户的流水，属于**集团内往来**

页面顶部可切换"全部主体 / 某一主体"，所有页面和报表随之过滤。

### 3.2 账户 —— 钱所在的地方
任何能"持有钱"的地方都是账户：

| 类型 | 示例 | 说明 |
|---|---|---|
| 公司对公账户 | 擎宇基本户、凌岳迭部分公司基本户 | 属于某一主体，可导入银行流水对账 |
| 内部个人账户（代管） | 张xx 个人银行卡、张xx 微信/支付宝 | 员工替公司代收代付，系统追踪"公司的钱在他手里还有多少" |
| 现金账户 | 张xx 持有现金、公司保险柜 | 可按持有人区分 |
| 外部往来账户 | 李老板个人、李老板公司对公户、供应商 X | 交易对手，记录资金去向/来源 |
| 特殊账户 | 税务机关（国库）、社保、银行手续费、期初 | 资金的终点或起点，用于税费/费用落地 |

账户信息：名称、类型、持有人/所属单位、开户行与账号、期初余额、是否启用、备注。内部个人账户名单由管理员在系统中录入。

> 关键指标：**内部个人账户和现金账户的余额 = 公司资金在个人手中的沉淀**，用于判断"钱有没有花完、有没有落袋"。

### 3.3 资金流水 —— 一次资金移动
每条流水 = 钱从账户 X 到账户 Y 的一次移动，记录：

- 日期、金额
- 转出账户、转入账户
- 流转方式：银行转账 / 微信 / 支付宝 / 取现 / 存现 / 现金交付 / 对公转账 / 冲销
- **所属项目**（必填，公司日常开销归入"公司公共"项目）
- **账目类型**（见第 5 节）
- 公司主体（由对公账户自动带出）
- **账面摘要**（银行回单上的用途，如"支付王燕雪工资"）与**实际用途**（如"颐和小区房租 + 物业费"）；账目类型按实际用途选择，两者不一致的流水在报表中标出，供内部审计复核
- 经办人、凭证附件（转账截图、收据、发票）、备注
- 手续费可单独拆出；多笔手续费可合并记一行并关联对应的流水
- 状态：草稿 → 待审核 → 已确认 →（已冲销）
- 关联发票、关联审批单

**一笔流水可拆分到多个项目/类型**，例如一次采购 3 万，2 万属于项目甲材料费、1 万属于项目乙材料费。

### 3.4 资金来源与资金链 —— 核心需求 1
只有"A→张、张→李"两条流水，并不能说明"张给李的钱就是 A 给张的那笔"。因此规定：

> 钱从**内部个人账户或现金账户**流出时，必须注明这笔钱来自该账户此前的哪几笔入款、各多少。

业务规则（已确认）：
- **出款即时注明来源**：个人/现金账户的每一笔出款，保存时必须注明来源，来源合计等于出款金额，否则不能保存，不允许"先记账、后补来源"
- 系统默认按"先进先出"自动填好来源，用户可在保存前调整
- 出款金额不能超过该账户尚未用掉的入款；不够时提示"请先录入该账户的资金来源"
- **期初资金**：上线时个人/现金账户已有的余额，以一笔"期初入款"录入，作为后续追溯的起点
- **冲销联动**：要冲销的入款如果已被后续出款用作来源，必须先冲销后续流水，系统会列出受影响的链路
- 支持**拆分**：A→张 10 万，张→李 6 万现金 + 张→供应商 3 万 + 张手里剩 1 万
- 支持**合并**：张的 6 万来源于 A 转入的 4 万 + B 转入的 2 万
- 公司对公账户默认视为资金池，不要求逐笔注明来源（待确认，见第 9 节）

由这些来源关系，系统自动串出每笔钱的**资金链**：

```
公户A ──10万──► 张xx个人卡 ──取现6万──► 张xx现金 ──交付6万──► 李老板
                    │                                         │
                    ├──3万──► 供应商X（材料费·项目甲）           │ 对公转入 5.8万
                    │                                         ▼
                    └── 滞留1万（待核销）                   公户B
```

资金链能回答：
1. **钱去了哪**：从任意一笔出款看最终去向——变成费用（材料/工资/税）、回到公户，或仍滞留在某人手里
2. **钱从哪来**：从任意一笔入款（如公户 B 收到 5.8 万）倒查源头
3. **链路状态**：
   - `进行中`：还有钱滞留在个人/现金账户
   - `已闭环`：钱已全部变成费用或回到公户
   - `异常`：滞留超过 N 天，或金额对不上（如交付 6 万只回来 5.8 万）
4. **差额说明**：链上金额对不上时必须说明差额去处（手续费、税点、返点、坏账、其他），保证每一分钱都有去处

### 3.5 项目 —— 核心需求 2、3
- 基本信息：编号、名称、客户、负责人、起止日期、状态（筹备/进行中/已结项/已归档）
- 合同额、预算（可按账目类型拆分：材料预算、人工预算……）
- 项目成员（用于工资/报销归属）
- 支持"项目 → 子项目/阶段"两级
- 所属公司主体（必填）
- 每个主体另有两个特殊项目："公司公共"（管理费用）和"未分配"（导入时暂未识别项目的流水）

### 3.6 集团内往来
两端都是本平台主体对公账户的流水（如祺羽 → 擎宇 80000），系统**只记一条**，不会两边各记一笔：
- 自动生成双方的往来记录：转出方"其他应收—擎宇"，转入方"其他应付—祺羽"
- 需选择性质：借款 / 还款 / 代付 / 劳务结算 / 资金调拨
- 导入两家公司的银行流水时，系统按金额、日期、对方户名自动配对，避免重复入账
- 往来余额表：任意两主体之间的累计净额
- 看"全部主体"时，集团内往来**不计入收入和支出**

## 4. 功能需求

### 4.1 工作台（首页）
- 我的待办：待审核流水、待我审批的报销、导入待处理事项
- 关键指标：本月收入 / 支出、各公户余额、**个人代管资金总额**（员工手里还有多少公司的钱）、异常资金链数
- 项目排行：支出 Top N、预算超支预警

### 4.2 项目管理
- 项目列表：按状态/负责人/时间筛选，显示合同额 / 已收 / 已支 / 预算执行率 / 毛利
- **项目详情页**（主工作界面）
  - 概览：收支汇总、按账目类型的构成、按月趋势、预算 vs 实际
  - 流水：本项目全部流水，可直接新建
  - 资金链：本项目相关的所有资金链及其状态
  - 工资 / 报销 / 材料：分类明细
  - 税费：本项目进项、销项、代扣个税等
  - 附件：合同、发票、凭证集中查看
  - 结项：结项前检查（无滞留资金、无待审核流水、无未说明差额），生成项目结算单（可导出 PDF/Excel）

### 4.3 账户管理
- 账户列表，按类型分组，显示当前余额
- 账户详情：流水明细、余额变化、（个人/现金账户）滞留资金及滞留时长
- **对账**：导入银行流水 → 与系统流水自动匹配（金额、日期、对方户名）→ 未匹配的人工处理 → 核对期末余额

### 4.4 流水录入
- **快速录入**：一屏完成，账户/项目/类型可搜索并记住最近使用；金额自动千分位、显示大写金额
- **连续流转录入**：针对核心需求 1 的典型场景，一次录完整条链：
  `第1步 公户A → 张xx 10万` → `第2步 张xx → 现金 6万（自动带出来源）` → `第3步 现金 → 李老板` → …
  每一步自动建议上一步的剩余金额，结束时显示链路预览并提示未闭环金额
- 分摊：一笔拆多个项目/类型，按金额或比例
- 附件：拖拽上传、手机拍照上传、粘贴截图；识别转账截图金额与日期（二期）
- 冲销：已确认的流水不能修改或删除，只能"冲销"后重新录入，保留痕迹
- 批量操作：批量改项目、批量提交审核

### 4.5 资金链查看
- 图形展示（节点 = 账户，连线 = 流水，粗细代表金额），可向前/向后展开，点击查看明细
- 列表：所有链路，按状态（进行中/已闭环/异常）、发起账户、项目、滞留天数筛选
- 滞留提醒：个人/现金账户资金滞留超过设定天数（如 30 天）时提醒经办人和财务

### 4.6 审批流程（轻量）
- 报销申请：员工提交 → 项目负责人审批 → 财务审核 → 付款（生成流水）
- 付款申请：超过设定金额需老板审批
- 审批环节可配置；企业微信/钉钉消息提醒（二期）

### 4.7 Excel 导入导出 —— 核心需求 4
**导入**
- 可导入：流水、账户、项目、工资表、报销单、银行流水（常见银行格式，可自定义列对应关系并保存）
- 流程：上传 → 对应列 → **预览检查**（逐行标出问题：账户不存在、项目不存在、金额或日期有误、疑似重复）→ 修正或跳过 → 确认导入 → 导入报告
- 账户/项目名称近似匹配，匹配不上的可一键新建或归入"未分配"
- 自动识别重复流水
- 整批导入可撤销（未被后续流水引用前）
- 提供标准模板下载（带下拉选项和填写说明）

#### 4.7.1 标准导入模板
模板第 1 行为表头，第 2 行为填写说明；主体、账户、项目、类型提供下拉选择。`*` 为必填。模板中不使用公式和合计行，汇总由系统计算。

**① 账户日记账模板（主模板，延续现有习惯）**
一个 Sheet 对应一个账户，版式接近现有日记账：

| 列 | 说明 |
|---|---|
| 交易日期* | 日期格式 |
| 对方户名* | 内部个人/现金账户、本平台其他主体从下拉选择 |
| 账面摘要 | 银行回单上的用途 |
| 收入 / 支出* | 均填正数，二选一 |
| 项目* | 下拉 |
| 账目类型* | 下拉，`一级/二级` |
| 实际用途 | 与账面摘要不同时必填 |
| 税种 / 所属期 | 对方为国库、社保时必填 |
| 发票号 | 多个用 `;` 分隔 |
| 银行流水号 | 用于去重与对账 |
| 余额（核对用） | 可选；填写后系统逐行核对，不一致即提示 |
| 备注 | 自由填写，不合并单元格 |

表头区填写：公司主体*、账户*、期间*；期初余额由系统带出。

**② 通用资金流水模板**（个人账户、现金等不经过公户的流转）
| 列 | 说明 |
|---|---|
| 日期* | — |
| 转出账户* / 转入账户* | 下拉选择 |
| 金额* | 正数，最多两位小数 |
| 流转方式* | 银行转账/微信/支付宝/取现/存现/现金交付/对公转账 |
| 项目* | 项目编号或名称 |
| 账目类型* | 如 `项目材料费/主材` |
| 账面摘要 / 实际用途 | 同上 |
| 经办人 | — |
| 银行流水号 | 用于去重与对账 |
| 发票号 | 多个用 `;` 分隔 |
| 来源流水号 | 可选；个人/现金账户出款时指定资金来源，留空则按先进先出自动分配，分配不了的行报错 |
| 备注 | — |

> 两种模板导入同样要求个人/现金账户出款注明来源：同一批导入的数据按日期排序处理，后面的出款可以以前面的入款为来源。

**③ 工资表模板**：公司主体*、所属月份*、人员*、身份证后四位（核对用）、所属项目（多项目按比例）、应发*、社保个人、公积金个人、个税*、其他扣款、实发*、社保单位、公积金单位、发放账户*、发放日期*

**④ 报销单模板**：报销单号*、报销人*、公司主体*、项目*、报销类型*、发生日期*、金额*、发票号、事由、付款账户、付款日期

**⑤ 主体模板**：名称*、简称*、统一社会信用代码、类型（总/分/独立）*、上级主体、纳税人身份*、身份生效日期*、所在地*、增值税申报周期*

**⑥ 账户模板**：账户名称*、账户类型*、所属主体（对公账户必填）、持有人/所属单位、开户行、账号、期初余额、期初日期

**⑦ 项目模板**：项目编号*、项目名称*、所属主体*、客户、负责人*、项目所在地、开始日期、结束日期、合同额、计税方式（一般计税/简易计税）、预算（按类型分列）、上级项目

**⑧ 银行流水**：不设固定模板，导入时指定各列含义（交易日期、收/支金额、对方户名、对方账号、流水号、摘要），每家银行的设置可保存复用。**今后推荐直接导入网银导出的流水**，财务只需补项目和类型，不必手抄日记账。

#### 4.7.2 历史数据迁移（已确认：人工完成）
- 现有日记账由财务**人工转录**到新模板后导入
- 历史资金链同样用新模板表达：同一笔钱的各步流转填写相同的**链路号**（如 L001），系统在同一链路内按先进先出分配来源；需要精确指定时填写来源引用
- 建议顺序：主体 → 账户（含期初余额）→ 各对公账户日记账 → 个人/现金账户流水；同一批可上传多个文件
- 两家主体日记账里都出现的同一笔往来，导入时自动配对，不重复入账

**导出**
- 任何列表页按当前筛选条件导出
- 报表导出：项目结算单、项目收支明细、账户余额表、个税/社保汇总、资金链明细（含来源关系）

### 4.8 报表与分析
- 项目收支汇总表、项目利润表（管理口径）
- 按账目类型 / 月份 / 人员的交叉分析
- 人员维度：某人经手资金、领取工资、报销总额、当前代管余额
- 往来分析：与某外部单位（李老板等）的累计往来与净额
- 预算执行分析与超支预警

### 4.9 系统管理
- 用户、角色、数据权限（主体 / 项目 / 账户）
- 基础资料：账目类型、流转方式、税率、银行流水格式
- 会计期间与**结账**：结账后该期间流水锁定，修改需反结账并留痕
- 操作记录：谁在何时对什么数据做了什么，修改前后内容

## 5. 账目类型 —— 核心需求 5

两级类型（管理员可维护），每个类型区分支出/收入/内部划转：

| 一级 | 二级示例 | 需额外填写 |
|---|---|---|
| **人员工资** | 基本工资、绩效奖金、加班费、劳务费（非雇员）、年终奖 | 人员、所属月份、应发、社保个人、公积金个人、个税、实发 |
| **项目材料费** | 主材、辅材、设备采购、设备租赁、运输费 | 供应商、规格/数量/单价（可选）、发票号、进项税 |
| **人员报销** | 差旅（交通/住宿/补贴）、餐饮招待、办公用品、通讯、其他 | 报销人、报销单号、发票张数、审批单 |
| 外包/分包费 | 劳务分包、专业分包 | 分包商、合同号、发票 |
| 税费 | 增值税、附加税、企业所得税、个税代缴、印花税 | 所属期、税种 |
| 社保公积金 | 单位部分、个人部分 | 所属月份、人员 |
| 管理费用 | 房租、水电、软件服务 | — |
| 财务费用 | 银行手续费、利息 | — |
| 项目收入 | 合同款、预付款、进度款、尾款 | 客户、发票（销项） |
| **内部划转** | 公户互转、公户→个人代管、取现、存现、现金交付、回流 | 不计入项目损益，仅用于资金链 |
| 往来款 | 借款、还款、押金、保证金 | 对方、预计归还日期 |

> 重要规则：**内部划转不计入项目成本**，只有钱真正花出去变成费用时才计入项目支出，避免同一笔钱在链路上被重复统计。

### 5.1 工资
- **个税不在本系统计算（已确认）**：每月导入已算好的工资表（含个税），系统只做核对和拆分记账：
  - 核对：应发 − 社保个人 − 公积金个人 − 个税 − 其他扣款 = 实发，不平的行不予导入
  - 拆分：实发（→员工）、个税（→税务机关，代扣代缴）、社保个人/单位（→社保）、公积金
- 工资可按工时/比例分摊到多个项目
- 生成工资汇总表、个税申报辅助表

### 5.2 报销
- 报销单含多行明细，每行可关联发票
- 借款核销：员工预借款可用后续报销冲抵，余额自动计算

## 6. 税费 —— 核心需求 6

**税费以公司主体为单位计算**，按该主体在业务发生期间的纳税人身份适用规则。分公司（如中汉夏河县分公司、凌岳迭部分公司）**独立报税**（已确认）。税率、征收率、免征额、优惠政策均可在系统中配置并注明生效日期，政策调整时直接新增规则。

### 6.1 两类纳税人的差异

| 项 | 一般纳税人 | 小规模纳税人 |
|---|---|---|
| 增值税计算 | 销项税额 − 可抵扣进项税额 | 不含税销售额 × 征收率（3%，现行优惠 1%） |
| 适用税率 | 13% / 9%（建筑服务）/ 6% / 简易计税 3%（清包工、甲供材等可选） | 征收率 |
| 进项抵扣 | 专票可抵扣，记录认证/勾选状态 | **不可抵扣**，进项税额计入成本 |
| 申报周期 | 通常按月 | 通常按季 |
| 免征 | — | 季度销售额不超过免征额（如 30 万）免征增值税，系统按季度累计自动判断 |
| 附加税 | 城建（7%/5%/1% 按所在地）+ 教育附加 3% + 地方教育附加 2% | 同左，可叠加"六税两费"减半等优惠 |
| 项目成本口径 | 不含税成本 | 含税成本 |
| 预缴 | 跨地区建筑服务按规定预缴（如 2%） | 跨地区预缴（如 1%） |

### 6.2 具体场景

| 场景 | 处理方式 |
|---|---|
| 增值税（销项） | 登记项目收入时录入开票信息：含税金额、税率或征收率（按主体身份给出可选项），税额自动计算 |
| 增值税（进项） | 材料/分包费用关联采购发票，区分专票/普票；一般纳税人专票计入可抵扣进项，小规模主体所有进项计入成本 |
| 跨地区预缴 | 项目所在地与主体所在地不同时，按收款额提示预缴，记录预缴税款并在申报时抵减 |
| 附加税 | 按应纳增值税 × 附加税率自动估算，叠加适用的减免 |
| 缴税流水 | 付给"国家金库XX支库"的款项必须注明税种（增值税/附加/个税/社保/印花税等）和所属期 |
| 个人所得税 | **不计算，导入已算好的结果**；系统负责记账、按人/按月/按项目汇总，并与实际缴税核对 |
| 企业所得税 | 管理口径估算，展示于利润表，不作为申报依据 |
| 资金链中的税点损耗 | 如个人取现、第三方代开票产生的税点/手续费，作为差额说明计入税费或财务费用 |

**发票管理**
- 发票台账：发票号、代码、类型、开票方/受票方、金额、税额、税率、开票日期、状态（未认证/已认证/已作废）、关联流水
- 发票与流水可多对多关联；"有付款无发票""有发票无付款"自动提示
- 发票号码重复提示；导入电子发票台账、识别与验真（二期）

**税费报表**
- 主体税负表：各主体按申报周期的销项、进项、应纳增值税、附加、税负率；小规模主体显示季度累计销售额及距免征额的余量
- 项目税负表：项目维度的同口径数据
- 月度/季度税费汇总、个税汇总、已缴与应缴核对

**项目利润（管理口径）**
```
一般纳税人：项目毛利 = 不含税收入 − 不含税成本 − 不可抵扣进项 − 附加税
小规模：    项目毛利 = 不含税收入 − 含税成本 − 附加税
```

## 7. 使用体验要求

- **以项目为中心**：任何页面都能快速切换到某个项目
- **录入要快**：键盘即可完成录入，常用账户、项目、类型自动记忆，支持"复制上一条"
- **金额要清晰**：统一千分位、两位小数，收支颜色区分，大额显示大写金额确认
- **钱的去向一眼可见**：每条流水都能看到它所在的资金链
- **错误提前拦截**：余额不足、疑似重复、项目已结项等在保存前提示
- **操作可追溯**：每条数据都能查看修改历史
- **手机可用**：报销提交、审批、拍照上传凭证可在手机上完成
