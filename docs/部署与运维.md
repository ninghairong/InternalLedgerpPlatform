# 部署与运维

## 部署（Docker Compose）

一台服务器即可（内网或云主机，2 核 4G 起），需安装 Docker。

```bash
git clone <仓库地址> ledger && cd ledger
cp .env.example .env      # 修改 DB_PASSWORD、JWT_SECRET、ADMIN_PASSWORD
docker compose up -d --build
```

浏览器访问 `http://服务器:8080`，用 `admin` 和 `.env` 中的 `ADMIN_PASSWORD` 登录，**立即在右上角修改密码**，再到"系统设置 → 用户"添加其他使用者（≤ 5 人）。

两个容器：

| 容器 | 说明 | 数据卷 |
|---|---|---|
| `db` | PostgreSQL 16 | `pgdata` |
| `app` | 后端 API + 前端页面，端口 8080 | `appdata`（`/data/attachments` 凭证附件、`/data/backups` 备份） |

启动时自动执行数据库迁移、补齐基础数据（账目类型、系统虚拟账户、税务规则、首个管理员）。不会载入演示数据。

> 生产环境建议删除 `docker-compose.yml` 中 `db` 的 `ports`，数据库不对外开放；需要 HTTPS 时在前面加一层 Nginx / Caddy 反向代理。

## 初始化数据

按"主体 → 账户（含期初余额）→ 项目 → 各对公账户日记账 → 个人卡 / 现金流水"的顺序，在"Excel 导入"中下载模板、填写、上传。可以放在同一批里一起上传，系统先处理主数据，再按日期统一入账。

## 升级

```bash
git pull
docker compose up -d --build     # 新的迁移脚本在启动时自动执行
```

## 备份与恢复

- **自动**：应用每天凌晨 2 点左右执行自检并备份到 `/data/backups`（数据库 + 附件），保留 30 天。"系统设置 → 备份"可查看、立即备份、下载。
- **异地**：备份和数据库在同一台机器上，请定期把备份文件复制到另一台机器或网盘（可在"系统设置 → 备份"中下载，或执行 `scripts/backup.sh` 生成到 `./backups/`）。
- **恢复**（会覆盖当前数据）：

```bash
scripts/restore.sh backups/ledger-20261103-020700.dump backups/ledger-20261103-020700-attachments.tar.gz
```

建议每季度在另一台机器上演练一次恢复。

## 日常检查

- "系统设置 → 数据自检"：四项全部通过即账务数据一致。不通过时请勿继续录入，联系管理员。
- "系统设置 → 审计日志"：所有新增、冲销、导入、导出、结账、登录都有记录，不可修改。
- 日志：`docker compose logs -f app`

## 常见问题

| 现象 | 处理 |
|---|---|
| 登录提示账号已锁定 | 连续输错 5 次锁定 15 分钟；管理员可在"用户"中重置密码立即解锁 |
| 冲销提示"已被 … 用作资金来源" | 先冲销下游流水，再冲销这一笔 |
| 记账提示"已结账" | 由管理员在"公司主体 → 结账"中反结账，改完后重新结账 |
| 端口 8080 已被占用 | 在 `.env` 中设置 `APP_PORT=其他端口` |
