# 内部账目管理平台 — 需求方案

> 版本：v1.0（已实现：前后端、数据库、Docker 部署） 日期：2026-11-03
> 来源：`require.md`

---

## 1. 背景与目标

公司内部资金流转存在大量"非标准路径"：公户转个人、个人取现、现金交付第三方、第三方再经对公账户回款等。传统记账软件只记录"公司账户的收支"，无法回答以下问题：

- 这 10 万元从公户 A 转出后，最终去了哪里？还有多少滞留在个人手里？
- 某项目到目前为止真实花了多少钱，其中材料、工资、报销各多少？税费多少？
- 李老板转入公户 B 的这笔钱，对应的是当初哪一笔出款？

**目标**：建立一个以**项目**为核心、以**资金流转链**为特色、账实可核对、可审计的内部账目平台。

### 1.1 现有台账分析（`excel/` 下 4 个文件）

现状：**每个公司主体一个 Excel，每个文件是一本"银行日记账"**，列为 `序号 / 交易日期 / 用途 / 收入 / 支出 / 余额 / 备注`。涉及主体：天津祺羽商贸、贵州中汉建设夏河县分公司、甘肃擎宇建设工程、甘肃凌岳建设迭部分公司（文件名前缀 27/28/29 说明主体还有更多）。

**发现的问题**（新系统需逐条解决）：

| # | 问题 | 实例 | 新系统对策 |
|---|---|---|---|
| 1 | **合计行公式范围错误**，合计数不对 | 擎宇 `合计 = SUM(D4:D17)`，实际数据到第 201 行；凌岳 `SUM(D4:D23)`、中汉 `SUM(D4:D21)` 同样 | 汇总全部由系统计算，不存手工合计 |
| 2 | 日期是文本且有笔误 | `20205.12.23`、2026 年序列中出现 `2025.1.16` | 日期控件录入；导入时校验格式与时间顺序，异常标红 |
| 3 | 收支符号不统一 | 支出列记负数，余额公式写成 `F+D--E`；擎宇第 181 行"收到结息 31.12"记在**支出列且为正数** | 金额一律为正，方向由转出/转入账户决定 |
| 4 | 浮点误差 | 余额显示 `147.100000000006` | 精确小数存储 |
| 5 | 序号跳号、空号、空用途 | 中汉 2→5；擎宇 155→157；擎宇末行只有 `-9` 无用途 | 系统自动编号；用途/类型必填 |
| 6 | **没有项目列**，项目写在合并单元格的备注里 | 凌岳 G21:G34 合并写"迭部县多儿乡布后村耕地围栏建设项目" | 项目为必填字段 |
| 7 | **没有账目类型**，"用途"列混写对方户名和用途 | `张磊`、`支付吴永兵工资`、`中华人民共和国国家金库迭部县支库`（实为缴税/社保） | 拆为"对方账户" + "账目类型" + "摘要" |
| 8 | 资金去向只能写在备注里，无法追踪 | "导账给张总（白总哥哥）10万元整，剩余1900元"、"回收款白总找的人"、"杨燕花找的人回收款" | 正是核心需求 1：用资金链 + 溯源分配记录 |
| 9 | 个人账户充当资金池，多家公司都与其往来 | 宁晓花、杨燕花在擎宇、凌岳都有大量"借款/还款" | 建为**内部个人账户**，跨公司统一追踪余额 |
| 10 | 公司之间互相往来，两边各记一笔无关联 | 擎宇"收到祺羽借款 80000"、凌岳"收到甘肃祺羽劳务费 47300" | **集团内往来**自动配对，合并报表时抵销 |
| 11 | 银行用途与实际用途不一致 | "支付王燕雪工资"备注为房租+物业费；"铁艺大门费"备注"实际购买布草条" | 同时记录**账面摘要**和**实际用途**，账目类型按实际用途；两者不一致的流水在报表中标记，供内部审计复核 |
| 12 | 批量手续费合并记一行 | "转账手续费 共12笔 -72" | 允许合并记录，可关联到对应的一批流水 |
| 13 | Sheet 名与标题期间不一致 | Sheet `2024.10月--12月`，标题 `2025.1.1-12.30` | 会计期间由系统管理 |
| 14 | 只有银行账户，没有现金和个人账户 | — | 账户体系覆盖公户、个人、现金、外部 |

结论：现有表格只能作为**历史数据迁移的来源**，不适合作为今后的录入模板。新模板见 4.7.1，历史数据迁移见 4.7.2。

### 1.2 非目标（第一期不做）
- 不替代正式财务软件出具法定报表，只提供管理口径数据；**不对接金蝶/用友等财务软件**（已确认）。
- **不做线上审批流**（已确认）：报销、付款在线下完成，系统只记录结果。
- **仅人民币**（已确认）：不支持外币与汇率。
- 不直连银行 API 自动拉流水（先用 Excel/CSV 导入银行流水，二期再考虑）。

## 2. 用户角色

平台为内部自用工具，**用户不超过 5 人**（已确认），权限从简：

| 角色 | 主要权限 |
|---|---|
| 管理员 | 系统配置、用户管理、内部个人账户名单、税务规则、结账与反结账，以及财务的全部权限 |
| 财务 | 录入与冲销流水、导入导出、对账、发票与税费 |
| 只读 | 查看全部数据与报表、导出 |

不做按主体 / 项目 / 账户的细粒度数据权限，所有用户可看到全部 30 家主体的数据。

## 3. 核心概念模型

```
           ┌──────────┐        ┌──────────┐
 项目 ◄────┤ 资金流水  ├───────►│  账户    │
 (Project) │ (Flow)   │ from/to│(Account) │
           └────┬─────┘        └──────────┘
                │ 1..n
           ┌────▼─────┐
           │ 溯源分配  │  (Allocation：本笔出款的钱来自哪几笔入款)
           └──────────┘
                │
           ┌────▼─────┐
           │ 资金链    │  (Trace：由分配关系自动串成的完整生命周期)
           └──────────┘
```

### 3.0 公司主体（Entity）—— 最顶层维度
平台同时管理 **n 个公司主体**，一般纳税人与小规模纳税人并存。

- 基本信息：名称、简称、统一社会信用代码、类型（总公司/分公司/独立公司）、上级主体（分公司挂总公司）、所在地、主管税务机关
- **纳税人身份**：一般纳税人 / 小规模纳税人，**带生效日期的历史记录**（小规模转一般纳税人后，之前期间仍按小规模计算）
- 税务配置：增值税申报周期（月/季）、适用税率或征收率、附加税优惠（如小规模"六税两费"减半）、所得税核定/查账征收
- 默认账户、负责会计

归属关系：
- 对公账户属于某一主体；**内部个人账户、现金账户不属于任何主体**（宁晓花、杨燕花同时为多家公司周转），由溯源分配记录每笔钱来自哪家公司
- 项目属于某一主体（承接合同的公司）；如一个项目由多家公司共同承担，按主体拆成子项目
- 每条流水的主体由所涉对公账户确定；两端都是本平台主体的对公账户时，为**集团内往来**

全局视角切换：顶部可选"全部主体 / 某一主体"，所有页面和报表随之过滤。

### 3.1 账户（Account）—— 资金所在的"节点"
任何能"持有钱"的地方都是账户，分类型：

| 类型 | 示例 | 说明 |
|---|---|---|
| 公司对公账户 | 擎宇基本户、凌岳迭部分公司基本户 | 属于某一主体；有银行账号，可导入银行流水对账 |
| 内部个人账户（代管） | 张xx 个人银行卡、张xx 微信/支付宝 | 员工替公司代收代付，系统追踪"公司资金在其手中的余额" |
| 现金账户 | 张xx 持有现金、公司保险柜 | 可按持有人区分 |
| 外部往来账户 | 李老板个人、李老板公司对公户、供应商 X | 交易对手，用于记录资金去向/来源 |
| 虚拟账户 | 税务机关（国库）、社保、银行手续费、期初 | 资金的"终点"或起点，用于税费/费用落地 |

账户属性：名称、类型、持有人/所属单位、开户行与账号（脱敏显示）、期初余额、启用状态、备注。

> 关键点：**内部个人账户和现金账户的余额 = 公司资金在个人手中的沉淀**，这是追踪"钱有没有花完、有没有落袋"的核心指标。

### 3.2 资金流水（Flow）—— 一次资金移动
每条流水 = 从账户 X 到账户 Y 的一次移动：

- 日期时间、金额（人民币）
- 转出账户、转入账户（二者之一可为外部账户）
- 流转方式：银行转账 / 微信 / 支付宝 / 取现 / 存现 / 现金交付 / 对公转账 / 抵扣冲销
- **所属项目**（必填，公司公共开销归入"公司公共"虚拟项目）
- **账目类型**（见第 5 节）
- 公司主体（由对公账户自动带出）
- **账面摘要**（银行回单上的用途，如"支付王燕雪工资"）与**实际用途**（如"颐和小区房租 + 物业费"）；账目类型按实际用途选择
- 经办人、凭证附件（转账截图、收据、发票）、备注
- 手续费 / 汇兑损益（可拆为子流水落到"银行手续费"虚拟账户）
- 状态：**正常 / 已冲销**。保存即生效，不设审核环节（已确认无审批需求）；已生效的流水不能修改或删除，只能冲销后重录。导入批次在未被批次外流水引用时可整批撤销
- 关联发票

**一笔流水可拆分到多个项目/类型**（分摊行），例如一次采购 3 万，2 万属于项目甲材料费、1 万属于项目乙材料费。

### 3.3 溯源分配（Allocation）与资金链（Trace）—— 核心需求 1
仅有"A→张、张→李"两条流水，系统并不知道"张给李的钱就是 A 给张的那笔"。因此引入**溯源分配**：

> 资金从**任何一个溯源账户**（对公账户、个人卡、现金）流出时，记录这笔出款的资金来源于该账户哪几笔入款、各多少。

**溯源范围（已确认：公户也逐笔溯源）**

| 账户类型 | 溯源要求 |
|---|---|
| 对公账户 | **强制**：每笔出款必须分配到该公户的具体入款 |
| 内部个人账户、现金 | **强制** |
| 外部往来账户 | 可选：用于把外部转回的钱接回原链路（如李老板收到现金后转回公户） |
| 虚拟账户（税务、手续费、期初等） | 不溯源，是资金链的终点或起点 |

- **强制即时溯源**：出款在**保存时**必须完成分配，分配合计 = 出款金额，否则不允许保存，不存在"先记账、后补溯源"。
- **默认分配规则：同项目优先，再先进先出**。系统优先使用该账户中**属于同一项目**的入款（如项目甲的回款优先支付项目甲的材料费），不够时再按入款日期从早到晚使用其他入款；录入时自动预填，保存前可手动调整。
- **可用余额校验**：出款金额不得超过该账户"未分配入款余额"之和；不足时拦截并提示"请先录入这笔钱的来源"。
- **期初资金**：系统上线时各账户已有的余额，以一笔"期初入款"（来源 = 期初虚拟账户）录入，作为后续溯源的起点。
- **冲销联动**：冲销某笔入款时，若其已被下游出款分配，必须先冲销下游（系统列出受影响流水），保证分配关系始终有效。
- 支持**拆分**：A→张 10 万，张→李 6 万现金 + 张→供应商 3 万 + 张手里剩 1 万。
- 支持**合并**：张的 6 万来源于 A 转入的 4 万 + B 转入的 2 万。

由分配关系，系统自动构建一个**有向无环图（DAG）**，即资金链：

```
公户A ──10万──► 张xx个人卡 ──取现6万──► 张xx现金 ──交付6万──► 李老板
                    │                                         │
                    ├──3万──► 供应商X（材料费·项目甲）           │ 对公转入 5.8万
                    │                                         ▼
                    └── 滞留1万（待核销）                   公户B
```

**资金链的起点**：每一笔从平台外进入溯源账户的钱，即项目回款、外部借款、期初余额、银行结息等。因为公户也逐笔溯源，一笔回款从进入公户开始，经过个人卡、现金、其他主体，直到最终花掉，全程可追。

**资金去向分类**（每条链的起始金额 = 以下各项之和）：

| 去向 | 含义 |
|---|---|
| 已落地 | 付出成为费用或税费（材料、工资、报销、税款、手续费等） |
| 往来流出 | 以往来款付给外部（借出、还款、押金等），正常结束 |
| 留存公户 | 还在对公账户中，尚未使用 |
| 滞留个人 / 现金 | 还在员工个人卡或现金中 |
| 外部待说明 | 以内部划转方式（如现金交付）交给外部后，没有转回也没有说明 |

资金链能力：
1. **正向追踪**：从任意一笔入款看"钱最终去了哪"。
2. **反向追溯**：从任意一笔入款（如公户 B 收到 5.8 万）回溯其源头。
3. **链路状态**：
   - `进行中`：仍有资金留存在公户或个人/现金账户；
   - `已闭环`：全部资金已落地或往来流出；
   - `异常`：个人/现金账户中滞留超过 N 天（默认 30 天，留存公户不算异常），或存在外部待说明金额（如交付 6 万只回来 5.8 万，差额需说明：手续费/返点/损失）。
4. **差额说明**：链上入出不平时必须挂一笔"差额处理"（手续费、税、坏账、其他），保证每一分钱都有去处。

### 3.4 项目（Project）—— 核心需求 2、3
- 基本信息：编号、名称、客户、负责人、起止日期、状态（筹备/进行中/已结项/已归档）
- 合同额、预算（可按账目类型拆分预算：材料预算、人工预算……）
- 项目成员（用于工资/报销归属）
- 层级：支持"项目 → 子项目/阶段"两级
- 所属公司主体（必填）
- 特殊项目：每个主体各有一个"公司公共"（管理费用）和"未分配"（导入时暂未识别的流水）

### 3.5 集团内往来
两端都是本平台主体对公账户的流水（如祺羽 → 擎宇 80000），系统**只记一条流水**，不会两边各记一笔：
- 自动生成双方的往来记录：转出方"其他应收—擎宇"，转入方"其他应付—祺羽"
- 性质需选择：借款 / 还款 / 代付 / 劳务结算 / 资金调拨
- 导入两家公司的银行流水时，系统按金额 + 日期 + 对方户名自动配对，避免重复入账
- 往来余额表：任意两主体之间的累计净额
- 合并视角（全部主体）下，集团内往来**不计入收入和支出**

## 4. 功能需求

### 4.1 工作台（首页）
- 提醒：异常资金链、个人/现金账户滞留资金、导入错误待处理、最近流水
- 关键指标卡：本月支出 / 收入、各公户余额、**个人代管资金总额**（员工手里还有多少公司的钱）、异常资金链数
- 项目排行：支出 Top N、预算超支预警

### 4.2 项目管理
- 项目列表：筛选（状态/负责人/时间）、卡片或表格视图，显示 合同额 / 已收 / 已支 / 预算执行率 / 毛利
- **项目详情页**（主工作界面）
  - 概览：收支汇总、按账目类型的饼图、按月趋势、预算 vs 实际
  - 流水 Tab：本项目全部流水，可直接新建
  - 资金链 Tab：本项目相关的所有资金链及其状态
  - 工资 / 报销 / 材料 Tab：分类明细
  - 税费 Tab：本项目进项、销项、代扣个税等
  - 附件 Tab：合同、发票、凭证集中查看
  - 结项：结项前校验（个人/现金账户中无本项目滞留资金、无未说明差额），生成项目结算单（可导出 Excel）

### 4.3 账户管理
- 账户列表，按类型分组，显示当前余额
- 账户详情：流水明细（带滚动余额）、未用完的入款及账龄（个人/现金账户超期预警）
- **对账**：导入银行流水 → 与系统流水自动匹配（金额 + 日期 ±N 天 + 对方户名）→ 未匹配项人工处理 → 生成对账结果；支持期末余额核对

### 4.4 流水录入
- **快速录入**：表单一屏完成，账户/项目/类型支持搜索 + 最近使用；金额输入自动千分位、大写金额回显
- **连续流转录入（向导）**：针对需求 1 的典型场景，按步骤一次录入整条链：
  `第1步 公户A → 张xx 10万` → `第2步 张xx → 现金 6万（自动带出来源）` → `第3步 现金 → 李老板` → …
  每一步自动建议上一步的余额，结束时显示链路图预览并提示未闭环金额
- 分摊：一笔拆多个项目/类型，按金额或比例
- 附件：拖拽上传、手机拍照上传、粘贴截图；支持 OCR 识别转账截图金额与日期（二期）
- 冲销：已确认流水不可修改/删除，只能"冲销"生成红字流水并重新录入，保留痕迹
- 批量操作：批量导出

### 4.5 资金链视图

模板为 `.xlsx`，第 1 行为表头，第 2 行为填写说明（导入时跳过），下拉项（主体、账户、项目、类型）从系统字典实时生成。`*` 为必填。**模板中不允许出现公式和合计行**，汇总由系统计算。

**① 账户日记账模板（主模板，延续现有习惯）**
一个 Sheet 对应一个账户，版式接近现有日记账，财务上手无门槛，但补齐了缺失的字段：

| 列 | 说明 | 对比现有表格 |
|---|---|---|
| 交易日期* | 日期单元格（非文本） | 原为文本，有笔误 |

| 实际用途 | 与账面摘要不同时必填 | 原在备注里 |
| 税种 / 所属期 | 对方为国库、社保时必填 | 原来没有 |
| 发票号 | 多个用 `;` 分隔 | 原来没有 |
| 银行流水号 | 去重与对账 | 原来没有 |

## 5. 账目类型设计

两级类型树（可扩展），每个类型有 方向（支出/收入/内部划转）与默认税务属性：

| 一级 | 二级示例 | 关键附加字段 |
|---|---|---|
| **人员工资** | 基本工资、绩效奖金、加班费、劳务费（非雇员）、年终奖 | 人员、所属月份、应发、社保个人部分、公积金个人部分、个税、实发 |

| **人员报销** | 差旅（交通/住宿/补贴）、餐饮招待、办公用品、通讯、其他 | 报销人、报销单号、发票张数 |
| 外包/分包费 | 劳务分包、专业分包 | 分包商、合同号、发票 |
| 税费 | 增值税、附加税、企业所得税、个税代缴、印花税 | 所属期、税种 |
| 社保公积金 | 单位部分、个人部分 | 所属月份、人员 |
| 管理费用 | 房租、水电、软件服务 | — |
| 财务费用 | 银行手续费、利息、汇兑损益 | — |
| 项目收入 | 合同款、预付款、进度款、尾款 | 客户、发票（销项） |
| **内部划转** | 公户互转、公户→个人代管、取现、存现、现金交付、回流 | 不计入项目损益，仅用于资金链 |
| 往来款 | 借款、还款、押金、保证金 | 对方、预计归还日期 |

> 重要规则：**内部划转不计入项目成本**，只有资金"落地"为费用类时才计入项目支出，避免同一笔钱在链路上被重复统计。

### 5.1 工资专项
- **个税不在本系统计算（已确认）**：按月导入已结算好的工资表（含个税结果），系统只做校验与拆分记账：
  - 校验：`应发 − 社保个人 − 公积金个人 − 个税 − 其他扣款 = 实发`（容差 0.01），不平的行标红拒绝导入
  - 拆分：实发（→员工）、个税（→税务机关，代扣代缴）、社保个人/单位（→社保）、公积金
- 工资可按工时/比例分摊到多个项目
- 生成工资汇总表、个税申报辅助表

### 5.2 报销专项
- 报销单含多行明细，每行可关联发票
- 借款核销：员工预借款可用后续报销冲抵，余额自动计算

## 6. 税费设计

**税务计算以公司主体为单位**，按该主体在业务发生期间的纳税人身份选择规则。所有税率、征收率、免征额、优惠政策都在"税务规则"字典中配置，**带生效起止日期**，政策调整时新增一条规则即可，不改代码。

### 6.1 两类纳税人的差异

| 项 | 一般纳税人 | 小规模纳税人 |
|---|---|---|
| 增值税计算 | 销项税额 − 可抵扣进项税额 | 不含税销售额 × 征收率（3%，现行优惠 1%，按规则配置） |
| 适用税率 | 13% / 9%（建筑服务）/ 6% / 简易计税 3%（清包工、甲供材等可选） | 征收率，无税率 |
| 进项抵扣 | 专票可抵扣；需记录认证/勾选状态 | **不可抵扣**，进项税额全部计入成本 |
| 申报周期 | 通常按月 | 通常按季 |
| 免征 | — | 季度销售额不超过免征额（如 30 万）免征增值税，系统按季度累计自动判断 |
| 附加税 | 城建（7%/5%/1% 按所在地）+ 教育附加 3% + 地方教育附加 2% | 同左，可叠加"六税两费"减半等优惠 |
| 项目成本口径 | 不含税成本 | 含税成本（进项不能抵扣） |
| 预缴 | 跨地区建筑服务按规则预缴（如 2%） | 跨地区预缴（如 1%） |

> 已确认：分公司（如中汉夏河县分公司、凌岳迭部分公司）**独立报税**，每个分公司按自身纳税人身份单独计算。

### 6.2 具体场景

| 场景 | 处理方式 |
|---|---|
| 增值税（销项） | 项目收入登记时录入开票信息：含税金额、税率或征收率（按主体身份给出可选项）、税额自动计算；支持不含税↔含税互算 |
| 增值税（进项） | 材料/分包费用关联采购发票，区分专票/普票；一般纳税人专票计入可抵扣进项，小规模主体所有进项计入成本 |
| 跨地区预缴 | 项目所在地与主体所在地不同时，按收款额提示预缴，记录预缴税款并在申报时抵减 |
| 附加税 | 按应纳增值税 × 附加税率自动估算，叠加适用的减免 |
| 缴税流水识别 | 付款给"国家金库XX支库"的流水必须细分税种（增值税/附加/个税/社保/印花税等）和所属期，不能只记"国库" |
| 个人所得税 | **不做计算，导入外部已结算结果**（工资表、劳务报酬表中的个税列）；系统负责记账、按人/按月/按项目汇总，并与实际缴税流水核对 |
| 企业所得税 | 管理口径估算，展示于利润表，不作为申报依据 |
| 资金链中的税费损耗 | 如个人取现、第三方代开票产生的税点/手续费，作为"差额处理"落地到税费/财务费用 |

**发票管理**
- 发票台账：发票号、代码、类型、开票方/受票方、金额、税额、税率、开票日期、状态（未认证/已认证/已作废）、关联流水
- 发票与流水多对多关联；"有流水无发票""有发票无流水"自动提示
- 发票号码去重校验；支持导入电子发票台账（二期：OCR/验真）

**税费报表**
- 主体税负表：各主体按申报周期的销项、进项、应纳增值税、附加、税负率；小规模主体显示季度累计销售额及距免征额的余量
- 项目税负表：项目维度的同口径数据
- 月度/季度税费汇总、个税汇总、已缴税款与应缴税款核对

**项目利润（管理口径）**
```
一般纳税人：项目毛利 = 不含税收入 − 不含税成本 − 不可抵扣进项 − 附加税
小规模：    项目毛利 = 不含税收入 − 含税成本 − 附加税
```

### 8.2 数据可靠性原则（"可靠的后端"）
1. **金额精度**：数据库 `NUMERIC(18,2)`（或以"分"为单位的 BIGINT），程序中禁用浮点；统一舍入规则（四舍五入至分，税额计算规则可配）
2. **不可篡改**：已确认流水只增不改，修正通过冲销 + 重录；结账期间锁定
3. **强一致**：一次业务操作（如连续流转、工资拆分）在单个数据库事务中完成；余额通过流水实时汇总或带版本号的余额表（乐观锁）维护，定期校验"余额 = Σ流水"
4. **幂等**：所有创建接口支持幂等键，防止重复提交；导入以批次 + 行指纹防重
5. **审计**：全量操作日志（用户、时间、IP、对象、变更前后 JSON），日志表只追加
6. **安全**：账号密码登录（失败锁定）；HTTPS（反向代理或自签证书）；敏感字段（银行卡号、身份证）加密存储、脱敏展示；按角色校验接口权限
7. **备份**：每日 `pg_dump` 全量备份 + 附件目录打包，保留 30 天，并复制到另一台机器或网盘；提供一键恢复脚本，定期演练
8. **自检任务**：每日定时校验 —— 账户余额一致性、溯源分配总额 ≤ 入款金额、资金链闭环状态、发票与流水匹配，异常推送管理员

### 8.3 核心数据表（`db/migrations/001_init.sql`）
```
app_user              用户（管理员 / 财务 / 只读）
entity                公司主体
entity_tax_profile    纳税人身份历史（生效区间不重叠，由排他约束保证）
tax_rule              税务规则（税率 / 征收率、免征额，带生效日期）
account               账户（对公 / 内部个人 / 现金 / 外部 / 虚拟；名称唯一）
account_balance       余额缓存（随分录更新）
category              账目类型（文本编码作主键）
project / project_budget  项目与分类预算（每个主体自动有一个"公司公共"项目）
accounting_period     会计期间（按主体按月结账）
flow                  资金流水（保存即生效；只能冲销 / 整批撤销）
flow_split            分摊行
ledger_entry          分录（入账 2 条、冲销再 2 条反向，只追加）
fund_lot              资金批次：流入溯源账户的每笔流水一个，记录剩余未用金额
flow_allocation       资金来源分配（出款 → 资金批次）← 资金链的边
lot_writeoff          外部账户差额核销
invoice               发票台账
payroll_batch / payroll_item  工资批次与明细
import_batch          导入批次（解析结果、逐行校验结果）
attachment / attachment_link  附件
audit_log             审计日志（只追加）
v_check_*             自检视图（余额 = 分录合计、溯源账户余额 = 未用完批次合计、来源合计 = 出款金额）
```
资金链不落表：由 `flow_allocation` 在内存中计算（与前端同一份代码），流水变动后自动失效重算。

### 8.4 资金链实现要点
- 溯源账户（公户、个人卡、现金）每笔入款维护 `remaining_amount`（未被分配的余额）；出款时按"同项目优先、先进先出"生成 `flow_allocation`，并在事务内扣减，带行锁（`SELECT … FOR UPDATE`）防并发超分配
- **强制溯源在服务端兜底**：保存出款的同一事务内校验 `Σ allocation.amount = flow.amount` 且每条来源 `remaining_amount ≥ 0`，不满足则整笔回滚；数据库层再加约束/触发器做最后防线
- 自检任务额外校验：每个溯源账户 `余额 = Σ 入款 remaining_amount`
- 资金批次由触发器在流水入账时自动生成，分配 / 释放 / 核销时由触发器增减剩余金额，`CHECK (0 ≤ 剩余 ≤ 原金额)` 防止超额
- 资金链：从根（外部来款、期初等）沿 `flow_allocation` 向下游展开，合并资金按金额比例归属；前后端用同一份代码在内存中计算，流水变动后自动重算

### 8.5 接口
- RESTful JSON，统一错误格式 `{ code, message }`，`message` 为可直接展示的中文说明；数据库规则抛出的错误同样转换为中文提示
- 主要接口：`/api/auth/*`、`/api/snapshot`（全量数据）、`/api/flows`（批量新建，支持 tempId 互相引用）、`/api/flows/:id/reverse`、`/api/lots/:id/writeoff`、`/api/imports`（上传 → 校验 → 提交 → 撤销）、`/api/templates/:code`、`/api/exports/:kind`、`/api/periods/*`、`/api/admin/*`
- 导入：`上传 → 返回逐行校验结果 → 跳过部分行后重新校验 → 提交（事务内对最新数据重新校验后写入）`；导出：请求后直接返回文件并记审计
